## 数据库设计

数据库名：`canteen`

| 表 | 作用 |
| --- | --- |
| `user` | 学生、商家、管理员账号 |
| `canteen_window` | 窗口名称、校区、楼层、位置、负责商家 |
| `category` | 菜品分类 |
| `dish` | 菜品、价格、库存、状态、销量 |
| `cart_item` | 用户购物车 |
| `order` | 订单主表、金额、状态、取餐码、预约时间 |
| `order_item` | 订单菜品明细 |

建表和初始数据脚本为 `docs/schema.sql`。

## 关键业务流程

### 学生点餐

学生登录后加载窗口、分类和菜品。加入购物车的数据按当前用户编号写入，避免客户端传别人的用户编号。提交订单时，系统读取购物车并按窗口分组，每个窗口生成一张订单，随后进入待支付状态。

### 支付与取消

模拟支付把订单从 `PENDING_PAY` 改为 `PAID`。学生只能支付或取消本人订单。取消未支付订单时，系统把订单中的数量回补到对应菜品库存，并把订单标记为 `CANCELLED`。

### 错峰取餐

下单时可以选择取餐时段。订单支付后系统保留取餐码，商家核验成功后才把订单改为 `PICKED`。这确保订单状态与现场交付动作一致。

### 权限控制

登录信息保存在 `HttpSession`。未登录请求返回 401，越权请求返回 403。管理员可以维护窗口和分类；商家只能查看和维护归属自己窗口的菜品与订单；学生只能查看和操作自己的购物车和订单。

## 接口摘要

| 模块 | 代表接口 |
| --- | --- |
| 认证 | `/api/auth/login`、`/api/auth/logout`、`/api/auth/me` |
| 食堂数据 | `/api/windows`、`/api/categories`、`/api/dishes` |
| 购物车 | `/api/cart`、`/api/cart/{id}` |
| 订单 | `/api/orders`、`/api/orders/{id}/pay`、`/api/orders/{id}/cancel`、`/api/orders/{id}/verify` |
| 统计 | `/api/stats/overview`、`/api/stats/export` |

所有接口统一返回 `Result(code, message, data)` 结构，前端据此处理成功与失败。

## 配置与运行

默认配置：

```properties
server.port=8080
spring.datasource.url=jdbc:mysql://localhost:3306/canteen
mybatis.mapper-locations=classpath:mapper/*.xml
```

可用环境变量覆盖：

| 变量 | 含义 |
| --- | --- |
| `DB_URL` | 数据库地址 |
| `DB_USERNAME` | 数据库用户名 |
| `DB_PASSWORD` | 数据库密码 |
| `SERVER_PORT` | 后端端口 |

开发模式：

```powershell
npm.cmd run dev
```

生产打包：

```powershell
mvn.cmd clean package -DskipTests
java -jar target\canteen.jar
```

## 已验证事项

- 三个演示角色可登录并进入对应首页。
- 学生可以浏览菜品、加购、下单、支付、取消和查看订单。
- 商家可以管理本窗口菜品、调整库存和核验取餐码。
- 学生访问管理端接口、他人订单或他人窗口菜品时返回 403。
- 管理员可查看统计、窗口、分类、用户和订单数据。
- 分类下仍有菜品时不允许删除。

## 已知边界

- 支付为模拟支付，不接入真实第三方支付。
- 角色权限已在主要接口落地，但若继续新增接口，应沿用 `UserSession.requireRole` 或明确的归属校验。
- 外部 Tomcat 的 WAR 部署步骤写在 README，默认交付仍以可执行 JAR 为准。
